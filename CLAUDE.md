# CLAUDE.md

Telemedicine web app for a hospital in Ghana (GHS currency, Paystack payments). Patients book and pay for consultations (General OPD or Surgical, online or in-person); doctors run video calls and write prescriptions after them; admins assign bookings, manage users, prices, site images, legal text and call recording.

## Stack & commands

- React 19 + Vite 8 + React Router 7, Tailwind v4 (via `@tailwindcss/vite`, imported in `src/index.css`) plus plain per-area CSS files (`admin.css`, `auth.css`, …). Plain JS/JSX, no TypeScript. Tests: server unit (`functions/test/unit`), emulator (`functions/test/emulator`, `tests/rules`), patient-page and admin logic (`components/patient/tests`, `components/admin/tests`; Node's test runner: pure `.js` modules only, imported with `.js` extensions) and end-to-end (`e2e/`, Playwright).
- Firebase (Blaze): Auth, Firestore (`eur3`), Storage, Cloud Functions v2 (Node 24, CommonJS, all in `europe-west1`) in `functions/`.
- Website on Firebase Hosting as an SPA (`firebase.json` → `hosting`: rewrites everything to `index.html`, headers, caching), published by GitHub Actions `deploy-website.yml` on push (main → live, test → test project) only after the security pipeline passes (it calls `security-audit.yml`: TruffleHog, ESLint, Semgrep, Snyk, GitGuardian, as its first job) with keyless Workload Identity Federation (HANDOVER.md "Website deploys"). Hosting is never deployed from a computer (`hosting.predeploy` → `scripts/hostingPredeploy.cjs` refuses outside GitHub Actions: always `firebase deploy --only …`); the workflow installs with `--ignore-scripts`, uses the lockfile-pinned CLI in `.github/firebase-cli`, and refuses builds with a debug token, emulator hosts or source maps. `src/canonicalHost.js` (`VITE_CANONICAL_REDIRECT=on`, live only after the domain switch) sends `*.web.app`/`*.firebaseapp.com` visits to `VITE_SITE_URL`. The hospital domain points at Firebase since 22 Oct 2026 (Cloudflare CNAME, DNS only, plus `_acme-challenge` TXT for renewals); Vercel is deleted.

```
npm run dev       # vite dev server
npm run build     # production build -> dist/
npm run lint      # eslint . (root config also lints functions/)
npm run preview
npm run test:rules   # Firestore/Storage rules tests on the emulators (needs Java 21)
npm run test:functions  # server tests (functions/test/unit + emulator) on the emulators
cd functions && npm test   # server unit tests only, no emulator
npm run test:e2e         # end-to-end robot tests (e2e/, Playwright 1.63) on the emulators
npm run test:patient     # patient-page logic (booking form, reschedule fees, dashboard grouping), no emulator
npm run test:admin       # admin logic (Overview figures, report periods and CSV export, audit names), no emulator
npm run deploy:functions -- --project live   # only the changed functions (default: test)
firebase deploy --only firestore,storage --project live   # or --project test
```

Two Firebase projects (`.firebaserc`): `test` = `telemedicine-hfch-test` (the **default** and `firebase use` choice, so a forgotten `--project` never reaches live) and `live` = `telemedicine-hfch` (always `--project live`). Owner scripts take the same `--project live|test` (`functions/scripts/project.js`, default test, printed first). Local `.env` holds the TEST web config; live's browser key doesn't accept `localhost` (HANDOVER.md "Test environment"). Project-specific values come from the environment, never hard-coded: `PROJECT_ID`/`RUNTIME_SERVICE_ACCOUNT` (core.js, from `GCLOUD_PROJECT`), `ENFORCE_APP_CHECK` (securityConfig.js; on in both projects, `ENFORCE_APP_CHECK=false` only for debugging), `SITE_URL` (mailConfig.js). `functions/.env.telemedicine-hfch-test` (committed, no secrets) sets those, `PAYMENT_REF_PREFIX=HFT` (payment references `HFT-…` there, `HFH-…` live: `lib/paystack.js` `newReference`/`isOurReference`, so neither project refunds the other's payments while they share Paystack's test account) and `SCHEDULED_JOBS=off`, which leaves every scheduled export out of `index.js` so the test project costs nothing. The test website is https://telemedicine-hfch-test.web.app (public but noindex: `VITE_SEARCH_INDEXING=off`; settings in the GitHub environment `test`, live's in `live`); the test project has its own Brevo/Cloudflare keys, its own reCAPTCHA key with App Check enforced, and a browser key restricted to that site. Staff accounts are created in the console (Add user) + `staffAdmin.js make-admin`, never via sign-up. GitHub "Automated tests" (`.github/workflows/rules-tests.yml`) runs unit, rules and emulator tests on pushes touching rules, functions or tests; emulator tests refuse a non-`demo-` project.

Husky pre-commit runs a trufflehog secret scan, then `lint-staged` → `eslint --fix` on staged `*.{js,jsx}`. ESLint includes `eslint-plugin-security`; `functions/**` uses Node globals, CommonJS, and double quotes.

Firebase config: `firebase.json`, `.firebaserc` (aliases `test` (default) and `live`), `firestore.rules`, `storage.rules`, `firestore.indexes.json`. `functions/scripts/staffAdmin.js` is run locally (never deployed) by a project Owner: `make-admin`, `reset-mfa`, `issue-setup-code`, `sync-claims`, and the one-off `enable-totp`, `password-policy`, `auth-recaptcha`. Day-to-day security procedures (new staff, lost phones, restores, alerts) are in `SECURITY_SETUP.md`.

## Layout

The code is split across two top-level folders. Both import from each other with relative paths (`../../src/firebase`).

- `src/` holds the app shell: `index.jsx` and `App.jsx` (all routes); `firebase.js` (exports `app`, `db`, `auth`, `functions` (europe-west1) — never call `getFunctions`/`getStorage` elsewhere); `firebaseStorage.js` (exports `storage`, kept separate so the Storage SDK only loads with pages that upload); `seo.js` (`usePageMeta`); `constants.js` (enum labels, `toDate`, Africa/Accra formatting, `callableMessage`); `consentText.js` (versioned booking consent — must match `functions/lib/consentText.js`); `doctorDirectory.js` (live listed `doctorProfiles`); `context/authContext.jsx`; `protectedRoutes.jsx`; auth pages; `siteSettings.js`; `legalDocs.js`.
- `components/` holds the feature areas:
  - `patient/`: `Home.jsx` (public landing, incl. open appointment slots under "Meet your doctors"; sections in `home/`), `bookConsultation.jsx` (booking + Paystack; "Myself" / "My child (under 18)"; checks and request in `bookingForm.js`, steps and callables in `booking/`), `dashboard/` (fee rules in `rescheduleRules.js`, grouping in `patientUtils.js`; tabs "My appointments" — bookings grouped Scheduled / Missed / Waiting to be scheduled, a "We're checking a payment" notice while a payment is in progress, open slots, history — and "Settings" (`patientSettings.jsx`: name, email); `patientFirestoreService.js`).
  - Doctor cards on Home show only photo, name, specialty, languages and "Sees patients for" (`doctorProfileDetails.jsx`): Ghana doesn't allow advertising doctors (medical director), so no bio, qualifications, experience or full-profile page. Patient-facing words are plain for lay readers ("Video call" / "At the hospital" = `MODE_LABELS`, "Booking reference", "Change appointment time"); keep new patient text that simple. Default mouse pointer (no custom cursor).
  - Patient pages are wrapped in `.patient-ui` (`PatientPage` in `App.jsx`), which raises Tailwind's `text-xs/sm/base` sizes (`src/index.css`) for readers of all ages. Keep patient text ≥14px and dark (`#3E4E56`, `black/70+`); staff pages keep defaults.
  - `doctor/`: `doctor.jsx` dashboard, `docFirestoreService.js`, profile tab, Prescriptions tab (`docPrescriptionsTab.jsx`), `prescriberDetails.jsx` + `signaturePad.jsx` (Account tab), `ui/` (incl. `prescriptionModal.jsx`).
  - `admin/`: `admin.jsx` shell with tabs (overview, bookings, history, users, call recordings, customer support (`customerSupportPanel.jsx`), revenue, audit, metrics, control panel incl. `recordingSwitchCard.jsx`). Metrics tab "Export a report" (`metricsExport.jsx`): month / quarter / year / custom (≤ 1 year) → `exportMetrics` (`functions/reports.js`, admins, audited, rate-limited; download needs a second admin, see Security model) returns tables built by `functions/lib/metrics.js` (revenue, bookings/consultations, quality of service, system, day- or month-by-month, by doctor; no patient details); saved as CSV (Excel, BOM, formula-guarded) or PDF via a print-only layout. Audit events are counted with aggregation (index `auditLog` code+timestamp); emails sent only for periods within the 30-day mail retention. `hooks/useFirestoreCollection.js` converts top-level Timestamps to Dates. Pure logic for tests: `adminStats.js` (Overview figures), `reportFormat.js` (report periods, CSV).
  - `video/`: WebRTC. `videoCallModal.jsx` shows the other person's whole picture, uncropped, on a blue background (a phone shows portrait on the room TV; the TV camera shows landscape on the phone). Hospital decision: no zoom/fill. `useWebRTCCall.js` imports signalling **only** through `signaling.js` → `signaling.firebase.js` (`calls/{consultationId}`, created by `startVideoCall`). `callRecording.js` records in the doctor's browser, but the server decides whether to record; it uploads 30 s segments that `finalizeRecording` stitches and hashes. TURN via `getTurnCredentials` (only a participant in the room now: join window + fresh `presence`, so credentials can't be collected ahead; on refusal the call falls back to STUN).
  - `shared/`: header, footer, `brandAside`, contact info (`contact.js`: phone and `SUPPORT_WHATSAPP`, both placeholders until launch), `supportButton.jsx` (floating button on every patient page via `PatientPage`, above Home's mobile booking bar: "Help" in-app messages for a signed-in patient with a verified email, lazy-loading `components/patient/support/`; WhatsApp "Chat with us" for everyone else).
- `functions/`: `index.js` lists every deployed function by name (nothing else deploys). Background tasks are `task(name, schedule, handler)` (`lib/task.js`), listed in `TASKS` in index.js and run by three Cloud Scheduler jobs from `jobs.js` (`jobsEveryMinute` incl. 5-minute tasks on minutes 0,5,…; `jobsEvery15Minutes` incl. hourly tasks at :00; `jobsDaily` 02:00 Accra): inside the 3 free jobs; tasks run independently. `scripts/deployFunctions.js` (`npm run deploy:functions`) deploys only functions whose require() chain changed since git tag `functions-deployed/<project>`. `lib/core.js` has the region, `requireRole`, validators, `audit()`, `rateLimit()`. Modules: `accounts`, `payments`, `prescriptions`, `scheduling`, `consultations`, `recordings`, `refunds`, `roomDevices`, `maintenance` (scheduled jobs), `siteSettings`, `legalDocs`, plus `email` and `reminders` (only deployed once email is configured).

## Routing & auth

Routes in `src/App.jsx`: public `/`, `/privacy`, `/terms`; `PublicOnlyRoute` for `/signin`, `/signup` and the staff path; `/verify-email`, `/unauthorized`; patient (verified email) `/dashboard`, `/book`; `/admin`; `/doctor`.

`authContext.jsx` is the single source of auth state (`useAuth()`). Read its header comment before changing auth.
- **Role comes from the `role` custom claim**, set only by functions (`registerPatient`, `createDoctorAccount`) and the `staffAdmin` script. The profile doc (`adminUsers/{uid}` for staff, `users/{uid}` for patients) must be `active`. No claim = no access; there is no patient fallback. `ProtectedRoute` fails closed on a null role.
- `signIn()` takes `audience: "patient" | "staff"`; an account on the wrong page gets the same generic error as a wrong password. Sign-up creates the Auth user then calls `registerPatient` (deletes the Auth user if that fails).
- Persistence is session-only by default; "Remember me" (patients only, ticked by default) switches to local. Idle sign-out: staff 30 min, patients 60 min; an open video call holds the session (`holdSession` in authContext, used by `videoCallModal.jsx`).
- **Staff inactivity on the server too:** `requireRole` (core.js `touchStaffActivity`) refuses a staff account idle more than 35 min (`adminUsers.lastActiveAt`; browser signs out at 30) and records activity at most once a minute; both rules files' `staffSecondFactor()` check the same (`staffNotIdle()`, missing field = allowed). The portals call `staffActivity` at most every 2 min while someone is active; call check-ins count. `confirmStaffSession` refreshes it only on a fresh sign-in (< 10 min), otherwise returns `idle` (the page signs out).
- Staff second factor: admins AND doctors use an authenticator app (Identity Platform TOTP). A factor counts only once pinned to `adminUsers.mfaFactorUid`, which needs a one-time setup code (`lib/staffSetup.js`, hash in `adminUsers.mfaSetup`, 72 h, 5 tries) issued by the staffAdmin script (admins) or an admin in the Users tab (doctors, `resetStaffAuthenticator`; `createDoctorAccount` returns one). Fresh sign-in every 12 h. Checked by `assertStaffSecondFactor` in `requireRole` (core.js) and `staffSecondFactor()` in both rules files. `functions/staffAuth.js confirmStaffSession` reports the next step (`totp_enroll`, `totp_signin`, `setup_code`, `setup_expired`, `ok`) and pins the factor. Sign-in UI: `signIn()` returns `{ step }`, rendered by `src/pages/auth/staffSecondFactor.jsx`; until done the account is held in `pendingStaffRef`, not exposed.
- App Check (reCAPTCHA Enterprise) is initialised in `src/firebase.js`; every callable is defined through `onCall` from `lib/core.js`, which applies `ENFORCE_APP_CHECK` (`functions/lib/securityConfig.js`, on since 11 Oct 2026; Firestore, Storage and Auth enforce it in the console). Sign-in reCAPTCHA stays in AUDIT: enforce mode blocked a genuine admin (SECURITY_SETUP.md). Never import `onCall` from firebase-functions directly.

## Security model (keep this intact)

- The browser is untrusted. Every write to bookings, consultations, payments, history, recordings, consents and the audit log is a Cloud Function (`requireRole` checks claim + active profile, inputs validated, rate-limited where abusable). Rules deny client writes except a doctor's own presentational `doctorProfiles` fields and call signalling (doctor writes `offer`, patient writes `answer`).
- Fees are computed on the server (`loadPrices()`, falling back to `DEFAULT_FEES`), by MODE: `prices.{online, in_person}` (General OPD and Surgical cost the same; no specialist surcharge). Keep `DEFAULT_PRICES` (`src/siteSettings.js`) and `DEFAULT_FEES` (`functions/siteSettings.js`) in sync. Payment is confirmed only by the signed Paystack webhook or verify-by-reference, idempotently. Amounts are whole GHS; ×100 happens only in `paymentIsAcceptable()` and when opening the popup.
- **Data retention (hospital decision):** booking details (age, sex, location, phone) live on `bookings` and `consultations.patientDetails` and are deleted when the consultation closes (`closeConsultation` in `lib/consultationLifecycle.js`: completed, or a no-show after its 14-day hold / refund / admin "Close now"); unpaid drafts are deleted after 24 h. Kept: `consultationHistory` (doctor, times, outcome, amount — patients see their own), `confirmedPayments`, `consents`, `auditLog`, `recordings`.
- **Call recording:** controlled only by the admin switch `systemSettings/features.callRecordingEnabled` (`setCallRecordingEnabled`), snapshotted per call in `calls.recordingEnabled`; both sides see REC from `calls.recordingActive`. Recordings carry patient/doctor names and a SHA-256. Admins play/download via 10-minute signed URLs with a reason, and delete singly or by date. All audited. No client can read the files.
- Playing or downloading a recording needs two admins too: `requestRecordingAccess` writes `accessRequests/{id}` (pending, 72 h), a different admin runs `decideRecordingAccess`; the requester then calls `getRecordingUrl({ requestId })` once within 24 h for a 10-minute signed URL. Never add a single-admin play/download path.
- Recording deletion needs two admins: `requestRecordingDeletion` writes `deletionRequests/{id}` (pending, 72 h), a different admin runs `decideDeletionRequest` (approve deletes, reject closes). Never add a single-admin delete path.
- Downloading a metrics report needs two admins (hospital decision, 13 Oct 2026): `exportMetrics` prepares it (the admin may view it), opens `reportRequests/{id}` (pending, 72 h; admin read) and keeps the report in `reportData/{id}` (no client access, so approval can't be bypassed); a new report replaces the admin's open one; `cancelReportRequest` (the preparer, any time); `decideReportRequest` (a different admin); `downloadReport` (the preparer, approved, within 24 h, once; data then deleted); daily task `cleanupReportData`. Audit `metrics.report_*`. Never add a single-admin download path.
- Prescriptions: only the patient and the doctor who wrote it read `prescriptions/{id}` (admins don't); signatures are never sent to a browser except a doctor's own (`doctorSignatures/{uid}`); the PDF is built on the server. Changing a doctor's MDC number or signature needs a sign-in under 5 minutes old (`requireFreshSignIn`; the Account tab calls `confirmIdentity` first). Never add an admin read or a client-built PDF.
- Patients must have an active `users/{uid}` profile in the rules (`isPatient()`), so deactivation takes effect immediately.
- Functions run as `functions-runtime@telemedicine-hfch.iam.gserviceaccount.com` (least privilege; `setGlobalOptions` in core.js). A new Google API used by functions may need a role added to it (see `SECURITY_SETUP.md`).
- Caller IP (consent, audit, per-IP limits) is `clientIp` in core.js: the right-most `X-Forwarded-For` entry, which Google appends (measured on test, 20 Oct 2026: `<caller-supplied>,<real>` via both run.app and cloudfunctions.net). Never `req.ip`: the Functions Framework trusts proxies, so it's the caller-written left-most entry. Per-address limits use `rateLimitIp` (hashed, alongside per-account ones: `registerPatient` 30/h, `createBookingDraft` 40/h; signed-out `checkPrescription`, `reportClientError`, forged-webhook audits); keep them generous (mobile carrier NAT).
- `mirrorAuditLog` copies each `auditLog` entry to Cloud Logging ("AUDIT" lines) → sink `audit-to-locked` → log bucket `audit-locked` (365 days, retention locked); the alert policy *Telemedicine security event* emails on security codes. Keep audit `code`s stable: the alert filter matches them.
- Consent: booking consent text is versioned; the server stores version + text hash + IP + time in `consents`. Never edit a published version — add a new one in both `consentText.js` files.

## Current state / gotchas

- Emails go to patients AND doctors through the `mail/{id}` outbox (`queueEmail` in `lib/mailQueue.js`, templates in `lib/emailTemplates.js`; doctor emails never include the patient's name or the consultation ID). Scheduling queues scheduled/rescheduled (patient) and assigned/rescheduled/unassigned (doctor). `reminders.js` (`sendAppointmentReminders`, every 5 min) sends 24 h and 1 h reminders to both, and a "not joined yet" email 1 min after an online start to whichever side hasn't joined (with the time they must join by), tracked in `consultations.reminders.*` (cleared on reschedule). Every confirmed booking also emails all active admins (`notifyAdminsNewBooking`, trigger on `bookingLog`). `functions/email.js` sends via `lib/mailProvider.js` (`MAIL_PROVIDER` in the project's functions env file `functions/.env.<project id>`: both projects use `brevo` (secret `BREVO_API_KEY`, since 13 Oct 2026); `resend` is the code default; only the chosen provider's secret is defined) and drops mail past `data.sendBefore`. The "is waiting, join before…" email (`queueWaitingEmail`) also sets `reminders.<role>Late`, so nobody gets it and the "not joined" reminder for one appointment. The email and reminder functions (and the `RESEND_API_KEY` secret) are only loaded when `lib/mailConfig.js` FROM isn't `@example.com`; the CLI refuses to deploy anything if a declared secret is missing. `bookings.lastEmail.status` shows admins whether the patient was emailed.
- Booking an open slot: the slot fixes doctor, type and mode. The booking page reads the slot and locks them; `createBookingDraft` refuses a different doctor or type (never silently overrides). An unpaid draft never holds its slot (else throwaway accounts could hold every open time): the slot is `held` only while Paystack reports a charge under way (`holdSlotForCharge` from `checkAttempts`, 15 min, renewed; `releaseSlotHolds` reopens it), taken by `markBookingPaid` (`slotLost` if someone paid first), and `initializePayment` refuses a slot already taken before Paystack opens. Free hospital visits still take their slot at once.
- Installable apps: patients get "Holy Family" (manifest `id` /dashboard, opens the dashboard); the staff pages (staff sign-in, admin, doctor; `src/staffApp.js` `useStaffAppManifest`) swap the manifest link to "Holy Family Staff" (`vite.config.js` `staffAppManifest`: `/staff-<sha256(path)>.webmanifest`, `id` /holy-family-staff, opens the staff sign-in), so a desktop install opens on staff sign-in.
- Doctors start/rejoin calls only from a registered telemedicine room computer: an admin registers it in Control panel (`registerRoomDevice`), its browser keeps `{id, key}` in localStorage (`src/roomDevice.js`), and `startVideoCall` requires an active key for doctors (`verifyRoomDevice`). Doctors never see the consultation ID. Patients join and request reschedules with one click (server checks they are the booked, verified patient); the ID is only a reference shown on their booking card and in emails.
- `startVideoCall` records who joined (`consultations.patientFirstJoinedAt`/`doctorFirstJoinedAt`, copied to `bookings.patientJoinedAt`/`doctorJoinedAt`, and `patientJoined`/`doctorJoined` on history) for the record. Whether a consultation took place is `metAt` (the two were connected): one with `metAt` can't be rescheduled or refunded; one without can (the reschedule resets the join fields, presence, `waitDeadline`, `metAt`, reminders and the `calls` doc).
- **No-shows** (`functions/noShow.js`, `lib/consultationLifecycle.js`): policy `siteSettings/public.noShow` {`waitMinutes`, `forfeitPercent`, `rescheduleFee`} set by admins (`updateNoShowPolicy`, Control panel "No-show policy"; `DEFAULT_NO_SHOW` in both `siteSettings.js`). **Video-call waiting rule** (`waitDeadline` in `lib/consultationLifecycle.js`, W = `waitMinutes`): nobody in the room by start + W = the doctor's no-show; when one side arrives in an empty room the other has until max(start, arrival) + W (`consultations.waitDeadline` {for, at}, mirrored on the booking); leaving early protects nobody (the countdown restarts for whoever left when the other arrives); once both are connected (`metAt`) it has taken place and no deadlines apply. Who's in the room = `consultations.presence.{doctor,patient}` from `startVideoCall` and `callHeartbeat` (call screen, every 15 s; `leaving` on close; present for 45 s). `metAt` (not the first-join fields) decides reschedule/refund eligibility and whether a doctor may close a video call as completed. `autoMarkNoShows` (every minute) and `callHeartbeat`/`startVideoCall` (`settleIfDue`) enforce it: patient → `markNoShow`, doctor → `markDoctorUnavailable` (+ `doctor_missed` email). Both call screens show the same countdown; the patient dashboard refreshes every 20 s while a room is open ("Your doctor is in the call, join before…"); the doctor portal every 30 s. In person: start + W; in-person ones are marked by the doctor ("Mark done" offers No-show only for hospital visits) or an admin. `markConsultationDone` refuses `no_show` from a doctor for a video call.
- **Doctor can't make it / call couldn't be completed** (`markDoctorUnavailable` in `lib/consultationLifecycle.js`, flag `doctorUnavailable.kind` `doctor_absent` | `call_incomplete`): the doctor ("I can't make it" before the two connect, "Call couldn't be completed" after, `reportDoctorUnavailable`), an admin (Bookings → Scheduled), or the waiting rule (doctor's deadline passed; doctor emailed `doctor_missed`). The patient's open call screen ends with an apology (`callHeartbeat` state). Sets `doctorUnavailable` {kind, at, by, byUid, reason (admin-only note, kept out of the audit log)} on the consultation and only {kind, at, by} on the booking (the patient can read it; admin.jsx reads the note from consultations) and a `rescheduleRequest` with `byHospital: true`; emails the patient (`patient_doctor_unavailable`) and every active admin (`admin_doctor_unavailable`, no patient name or link). If neither side turns up to a video call, it's the doctor's no-show: `rescheduleCountsAsNoShow` charges the patient's late reschedule only while the doctor is waiting for them, and the automatic check leaves a patient's own request alone only if it was made before the start or re-opened after their own no-show (`rescheduleRequest.afterNoShow`). Emails queued after the start time pass an explicit `sendBefore` (the default is the appointment time). Meanwhile no joining, reminders, no-show or "completed"; the doctor's list hides it; admins can't decline it. Admin reschedule clears the flag (patient email says sorry); it's allowed even after the two met when the doctor reported "call couldn't be completed" (`canBeRescheduled` in scheduling.js), and it clears `consultations.prescription` so the new call can have its own. Patient may instead ask for a full refund at once (`requestRefund` outcome `doctor_unavailable`); approving it closes as outcome `cancelled`. ## Quality gate for code changes

Make a change only if the answer to all four is yes. If one fails or the trade-off is unclear, skip the change and say why (naming the check).

1. **Secure:** no new injection/XSS risks, no secrets in code, inputs still validated, auth/permission checks unchanged or stronger (see Security model), error handling not weakened.
2. **Efficient:** removes real waste or keeps performance equal. No micro-optimisations that hurt readability for negligible gain.
3. **Maintainable:** a new developer would find it easier to understand and modify than before. No abstraction "just in case" (YAGNI); only consolidate duplication that is the same concept.
4. **Standards-compliant:** follows SOLID/DRY/KISS, the language's idioms, the project's lint rules and existing conventions (style, folder structure, patterns).

In a refactor, behaviour stays the same: report suspected bugs rather than fixing them silently, and ask before changing behaviour, public interfaces (callables, routes, data formats) or anything out of scope.
